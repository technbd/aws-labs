## AWS S3: 

Amazon **Simple Storage Service (S3)** is a fully managed cloud object storage service used to store and retrieve files/data from anywhere over the internet.




### Important S3 Terms:

| Term              | Meaning                                         |
| ----------------- | ----------------------------------------------- |
| **Bucket**        | Container where your files are stored           |
| **Object**        | Actual files stored in S3                       |
| **Object Key**    | Full path/name of an object                     |
| **Region**        | AWS geographic location where bucket is created |
| **Storage Class** | Determines cost/access characteristics          |
| **Versioning**    | Keeps multiple versions of an object            |
| **Lifecycle**     | Automatically moves/deletes objects and reduce storage costs |
| **Bucket Policy** | Controls access to bucket resources             |
| **Access Point**  | Provides application-specific access to S3      |
| **Encryption**    | Protects stored data                            |





### S3 Storage Classes:

AWS provides different storage classes for different access patterns: 

| Storage class | Designed for | Bucket type | Availability Zones | Min storage duration | Min billable object size | Monitoring and auto-tiering fees | Retrieval fees |
|---------------|--------------|-------------|-------------------:|---------------------:|-------------------------:|----------------------------------|----------------|
| **S3 Standard** | Frequently accessed data (more than once a month) with millisecond access | General purpose | ≥ 3 | - | - | - | - |
| **S3 Intelligent-Tiering** | Data with changing or unknown access patterns | General purpose | ≥ 3 | - | - | Per-object fees apply for objects ≥ 128 KB | - |
| **S3 Standard-IA** | Infrequently accessed data (once a month) with millisecond access | General purpose | ≥ 3 | 30 days | 128 KB | - | Per-GB fees apply |
| **S3 One Zone-IA** | Recreatable, infrequently accessed data (once a month) with millisecond access | General purpose or directory | 1 | 30 days | 128 KB | - | Per-GB fees apply |
| **S3 Glacier Instant Retrieval** | Long-lived archive data accessed once a quarter with instant retrieval in milliseconds | General purpose | ≥ 3 | 90 days | 128 KB | - | Per-GB fees apply |
| **S3 Glacier Flexible Retrieval** (formerly Glacier) | Long-lived archive data accessed once a year with retrieval of minutes to hours | General purpose | ≥ 3 | 90 days | - | - | Per-GB fees apply |
| **S3 Glacier Deep Archive** | Long-lived archive data accessed less than once a year with retrieval of hours | General purpose | ≥ 3 | 180 days | - | - | Per-GB fees apply |
| **Reduced redundancy** | Noncritical, frequently accessed data with millisecond access (not recommended as S3 Standard is more cost effective) | General purpose | ≥ 3 | - | - | - | Per-GB fees apply |





### Core BenefitsDurability: 
- **Durability**: Offers 99.999999999% (11 nines) of data durability by spreading data across multiple physical facilities.
- **Scalability**: Automatically grows your storage capacity as needed without requiring prior provisioning.
- **Consistency**: Provides strong read-after-write consistency for all data updates.
- **Security**: Keeps buckets private by default, allowing access control via Bucket Policies and AWS IAM.



### S3 vs EBS vs EFS:

AWS storage services, this distinction is important:
| Feature                | **S3**                        | **EBS**           | **EFS**           |
| ---------------------- | ----------------------------- | ----------------- | ----------------- |
| Type                   | Object storage                | Block storage     | File storage      |
| Attached to EC2        | No                            | Yes               | Via network       |
| Shared by multiple EC2 | Yes, through API              | Generally no      | Yes               |
| Typical use            | Files, backups, static assets | OS/database disks | Shared filesystem |
| Scalability            | Very high                     | Volume-based      | Elastic           |
| Example                | `backup.zip`                  | `/dev/xvdf`       | `/mnt/shared`     |




### Common Use Cases:
- **Backups and Recovery**: Storing secure, long-term copies of organizational data and system backups.
- **Data Lakes**: Acting as the foundation for petabyte-scale analytics, AI, and machine learning models.
- **Static Hosting**: Serving static website assets like HTML, CSS, and client-side scripts.
- **Media Storage**: Hosting large media libraries for user content, images, and video streaming.

## Create an S3 Bucket:

        - `Directory` (Recommended for low-latency use cases. These buckets use only the S3 Express One Zone storage class, which provides faster processing of data within a single Availability Zone.)
    - Bucket namespace:
        - ✅ `Global namespace` (By default, S3 creates general purpose buckets in the global namespace.)
        - `Account Regional namespace (recommended)` (General purpose buckets created in your account Regional namespace are unique to your account. These buckets can never be created by another AWS account.) 
    - Bucket name: `technbd-bucket-1`
    - Copy settings from existing bucket - optional: 
        - `Choose bucket`
    - **Object Ownership:** 
    - Object Ownership:
        - ✅ `ACLs disabled (recommended)`
        - `ACLs enabled`
    - **Block Public Access settings for this bucket:** (If this is just an AWS learning bucket, **keep Block Public Access enabled**.)
    - [ ] `Block all public access`:
        - [ ] Block public access to buckets and objects granted through new access control lists (ACLs)
        - [ ] Block public access to buckets and objects granted through any access control lists (ACLs)
        - [ ] Block public access to buckets and objects granted through new public bucket or access point policies
        - [ ] Block public and cross-account access to buckets and objects through any public bucket or access point policies
    - **Bucket Versioning**:
    - Bucket Versioning:
        - ✅ `Disable`

    - Tags - optional
    - **Default encryption**:
    - Encryption type:

3. Select your bucket `technbd-bucket-1` - click `Permissions` Tab - click `Edit` for **Bucket policy**: 

> If this is just an AWS learning bucket, **keep Block Public Access enabled**.

_So the key distinction is:_
```
S3 Bucket Policy
→ Principal is required
 
IAM Identity Policy
→ No Principal
```



_In an AWS policy, these three parts are very important:_
```
"Principal": "*",
"Action": "s3:GetObject",
"Resource": "arn:aws:s3:::technbd-bucket-1/*"
```

_Read it as:_
```
WHO → Principal
WHAT can they do? → Action
WHICH THING? → Resource
ALLOW or DENY?  → Effect
```



If your goal is simply to **open an S3 object in a browser**, you generally only need public `s3:GetObject`, not public upload/delete permissions:
- `Sid` : is simply a label describing the statement. Makes it easier to understand what the statement does when your bucket policy becomes larger.
- `*` : means everyone / anyone.



_Public bucket (to make objects publicly readable):_
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}
```


_Anyone (`"Principal": "*"`) can list the bucket, read objects, upload objects, and delete objects:_
- First statement — List the bucket
- Second statement — Object access 


```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3Access",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME"
    },
    {
      "Sid": "AllowObjectAccess",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}
```

**For CLI access, make sure your IAM user/role has permissions such as:**
- This JSON is an **IAM Identity Policy**, not an S3 Bucket Policy, because it has no Principal.



_If you want to give an **IAM user/role S3 access** (Private bucket: (recommended)):_

{

    {
      "Effect": "Allow",

### Method 2: Using the AWS CLI:



#### Create the S3 Bucket: 

_Run the following command in your terminal to create a S3 bucket:_
```bash
aws s3 mb s3://<BUCKET_NAME>

aws s3 mb s3://my-bucket-1
```



If you want to create the bucket in a specific AWS region outside your default configuration, use the `--region` flag along with a `LocationConstraint` configuration for regions other than `us-east-1`:

```bash
aws s3api create-bucket --bucket <BUCKET_NAME> --region ap-southeast-1 --create-bucket-configuration LocationConstraint=ap-southeast-1

aws s3api create-bucket --bucket my-bucket-2 --region ap-southeast-1 --create-bucket-configuration LocationConstraint=ap-southeast-1
```




_Verify:_
```
aws s3 ls
```


_Check Bucket Location:_
```
aws s3api get-bucket-location --bucket my-bucket-2
```



#### Upload: 

_Create a test file::_
```bash
echo "Hello from AWS CLI" > file.txt
```


_Upload:_
```bash
aws s3 cp file.txt s3://my-bucket-1
```



#### List Objects: 

```bash
aws s3 ls s3://my-bucket-1
```




#### Download the Object:

```bash
aws s3 cp s3://my-bucket-1/file.txt downloaded.txt
```



#### Upload a directory: 

```bash 
aws s3 cp /opt/myapp s3://my-bucket-1/myapp --recursive
``` 


_Verify:_
```bash
aws s3 ls s3://my-bucket-1 --recursive

aws s3 ls s3://my-bucket-1/myapp --recursive
```




#### Delete the Object:

```bash
aws s3 rm s3://my-bucket-1/file.txt

aws s3 rm s3://my-bucket-1/myapp/myfile.tx
```




#### Delete the Bucket: 

```bash
aws s3 rb s3://my-bucket-1
```

## Connect an EC2 Instance to S3 Bucket Using IAM Role Without Access Keys:

This is a good lab sequence: **Create S3 bucket** → **Create IAM policy** → **Create EC2 IAM role** → **Attach role to EC2** → **Test S3 access without access keys**.


### Create an S3 Bucket:

See up.


### Create IAM Role for EC2:

1. Open the **AWS IAM Console** - click `Roles` in the left menu - click `Create role`: 
    - Select trusted entity: 
        - Trusted entity type: ✅ `AWS service`
    - Use case:
        - Service or use case: select `EC2`
        - Use case: ✅ `EC2` 
    - Click `Next`
    - Add permissions: ✅ `Use existing policy`
    - Permissions policies: (search policy)
        - Policy name: ✅ `AmazonS3FullAccess`
    - Set permissions boundary - optional:
    - Click `Next`
    - Role name: `s3FullAccess-for-ec2`
    - Description: Allows EC2 instances to call AWS services on your behalf.
    - Step 1: Select trusted entities:
    - Step 2: Add permissions: 
    - Step 3: Add tags
    - Click `Create role`




### Attach IAM Role to EC2:

1. Open AWS **EC2 console**: 
    - Number of instances: `1`
    - Name and tags: `web-server-01`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` 
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `technbd-vpc`
        - Subnet: select subnet `public-subnet-1` 
        - Auto-assign public IP: `Enable`
        - Firewall (security groups): select existing security group (`public-web-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
        - File systems: `None`
    - Advanced details: 
        - IAM instance profile: `s3FullAccess-for-ec2`
        - User data - optional: 
    - Click `Launch instance`
