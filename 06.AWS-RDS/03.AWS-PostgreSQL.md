## PostgreSQL:

To set up an Amazon Relational Database Service (RDS) instance.



### Basic Architecture:

```
                        technbd-vpc
                        10.0.0.0/16 
                             │ 
            ┌────────────────┴────────────────┐ 
            │                                 │ 
        Public Subnets                Private Subnets 
        10.0.1.0/24                   10.0.11.0/24 
        10.0.2.0/24                   10.0.12.0/24 
                                           │ 
                                    ┌──────┴──────┐ 
                                    │             │ 
                                Private        Private 
                                Subnet 1       Subnet 2 
                                    │             │ 
                                    └──────┬──────┘ 
                                           │ 
                                    DB Subnet Group 
                                     (techbd-rds)
                                           │ 
                                           ▼ 
                                    ┌──────────────┐ 
                                    │ RDS PostgreSQL │ 
                                    │ pgsql18-db-1   │ 
                                    │                │ 
                                    │ Port 5432      │ 
                                    │ Private        │ 
                                    └──────────────┘
```



### Prerequisites:

- VPC
- At least 2 Availability Zones
- At least 2 subnets (two subnets should normally be in different Availability Zones)
- Security Group
- DB subnet group
- Optional EC2 instance for testing

## Create a Database on AWS RDS:


### Step 1: Create Security Groups


#### 1. Public Web Security Group:
1. Open the **VPC Console**.
    - Select `Security Groups` from the left menu under `Security` section, and click `Create security group`: 
        - Security group name: `public-web-sg`
        - Description: public-web-sg-for-technbd-vpc
        - VPC: select VPC `technbd-vpc`
        - **Inbound rules**:
            - Type:       HTTP 
            - Protocol:   TCP
            - Port:       80 
            - Source:     Anywhere IPv4 (0.0.0.0/0)
        - **Inbound rules**:
            - Type:       HTTPS 
            - Protocol:   TCP
            - Port:       443 
            - Source:     Anywhere IPv4 (0.0.0.0/0)
        - **Inbound rules**:
            - Type:       SSH 
            - Protocol:   TCP
            - Port:       22 
            - Source:     Anywhere IPv4 (0.0.0.0/0)
        - Click `Create security group` 


#### 2. Create RDS Security Group:
1. Open the **VPC Console**.
    - Select `Security Groups` from the left menu under `Security` section, and click `Create security group`: 
        - Security group name: `rds-sg`
        - Description: Security group for mysql/pgsql
        - VPC: select VPC `technbd-vpc`
        - **Inbound rules**:
            - Type:       `PostgreSQL` 
            - Protocol:   TCP
            - Port:       `5432` 
            - Source:     `Custom`
                - **Security Groups**: select `public-web-sg`
        - Click `Create security group`





### Step 2: Create DB Subnet Group

1. Open the **Amazon RDS** console and in the left navigation pane, under `Aurora and RDS` - click `Subnet groups` - click `Create DB subnet group`: 
    - Subnet group details:
    - Name: `techbd-rds`
    - Description: `MySQL/PostgreSQL private subnet group`
    - VPC: `technbd-vpc` 
    - Add subnets
        - Availability Zones: select `us-east-1a` and `us-east-1b` 
        - Subnets: select `private-subnet-1` and `private-subnet-2`
    - Click `Create`



### Step 3: Launch the RDS Instance

1. Open the **Amazon RDS** console and in the left navigation pane, under `Aurora and RDS` - click `Databases` - click `Create database` and select `Full configuration`:
    - Engine options: 
        - Select ✅ `PostgreSQL`
    - Choose a database creation method: 
        - Select ✅ `Full configuration`
    - Templates: 
        - ❌ Production
        - ❌ Dev/Test 
        - ✅ `Free tier` 
    - Availability and durability: 
    - Deployment options: 
        - ❌ Multi-AZ DB cluster deployment (3 instances)       (<-- AZ1: Write/read endpoint and AZ2-AZ3: Reader endpoints)
        - ❌ Multi-AZ DB instance deployment (2 instances)      (<-- AZ1: Write/read endpoint and AZ2: Standby (no endpoint))
        - ✅ Single-AZ DB instance deployment (1 instance)   (<-- AZ1: Write/read endpoint)
    - Settings:
    - Show filters: 
        - ✅ Show only versions that support the Multi-AZ DB cluster
    - Engine version: `PostgreSQL 18.3-R2`
    - [ ] Enable RDS Extended Support (<-- Unselect it)
    - DB instance identifier: `pgsql18-db-1`
    - Credentials Settings:
        - Master username: `postgres`
        - Credentials management: 
            - `Managed in AWS Secrets Manager - most secure`  (<-- Additional charges apply)
            - ✅ `Self managed` 
        - **Master password**: rdsadmin26
    - Additional credentials settings:
        - Database authentication options:
            - ✅ `Password authentication`
            - Password and IAM database authentication 
            - Password and Kerberos authentication 
    - Instance configuration: 
        - DB instance class:
        - Show filters: 
            - Include previous generation classes 
            - ❌ Standard classes (includes m classes)
            - ❌ Memory optimized classes (includes r and x classes)
            - ✅ `Burstable classes (includes t classes)`
        - Instance type: `db.t4g.micro` 
    - Storage: 
        - Storage type: `General Purpose SSD (gp3)`
        - Allocated storage: `20` 
        - Provisioned IOPS: `3000`
        - Storage throughput: `125`
        - Additional storage configuration: 
            - Storage autoscaling: ✅ `Enable storage autoscaling`
            - Maximum storage threshold: `1000`  (Allocated storage value must be 22 GiB to 6,144 GiB)
    - Connectivity:
        - Compute resource:
            - ✅ `Don’t connect to an EC2 compute resource`
        - Virtual private cloud (VPC): select VPC `technbd-vpc`  (**After a database is created, you can't change its VPC**)
        - DB subnet group: `techbd-rds`
        - Public access: `Yes` | ✅ `No` 
        - VPC security group (firewall): `rds-sg`
        - Availability Zone: `us-east-1b`
        - RDS Proxy: 
            - Create an RDS Proxy 
        - Certificate authority - optional: `rds-ca-rsa2048-g1 (default)`
        - Additional configuration: 
            - Database port: `5432`
    - Tags - optional: 
        - ENV: dev 
    - Monitoring : 
        - Database Insights - Advanced 
        - ✅ `Database Insights - Standard`
        - ✅ Collect detailed database and per-query metrics
        - Retention period: 7 days (free)
        - AWS KMS key: `(default) aws/rds`
        - Additional monitoring settings
            - Enhanced Monitoring: [ ] `Enable Enhanced monitoring`  (<-- By default Unselected)
        - Log exports: 
            - [ ] iam-db-auth-error log
            - [ ] PostgreSQL log
            - [ ] Upgrade log
        - IAM role: `RDS service-linked role`
    
    - Additional configuration:
        - Database options:
            - Initial database name: 
            - DB parameter group: `default.postgres18` 
            - Option group: `default.postgres18` 
            - ✅ Enable encryption
            - AWS KMS key: `(default) aws/rds`
        - Backup: 
            - ✅ `Enable automated backup`
            - **Backup retention period**: 1 day  (<-- For Free tier)
            - Backup window:
                - Choose a window
                - ✅ `No preference`
            - Backup tags:
                - Copy tags to automated backup
                - ✅ Copy tags to snapshots
            - Backup replication:
                - [ ] Enable replication in another AWS Region (<-- By default Unselected)
            - Maintenance:
                - ✅ Enable auto minor version upgrade
            - Maintenance window : 
                - Choose a window
                - ✅ `No preference`
            - [ ] Enable deletion protection (<-- By default Unselected, it prevent accidental deletion of the database)
    - Click `Create database`


2. Connect to the Database: select your new database `pgsql18-db-1` - click `Connectivity & security` Tab:
    - Click ✅ `Endpoints`
        - Database name: postgres
        - Master username: postgres
        - Internet access gateway: Disabled
        - Port: 5432
        - Endpoint type: `Instance endpoint`
    - Additional configurations:
    - Endpoint & port:
        - Endpoint: `pgsql18-db-1.xxxxxxxx.us-east-1.rds.amazonaws.com`
        - Port: `5432` 








### Step 4: Connect to the EC2 Instance 

1. Open AWS **EC2 console**: 
    - Number of instances: `1`
    - Name and tags: `web-server-01`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` 
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `technbd-vpc`
        - Subnet: select subnet `public-subnet-1` 
        - Auto-assign public IP: `Enable`
        - Firewall (security groups): select existing security group (`public-web-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
        - File systems: `None`
    - Advanced details: 
        - User data - optional: 
    - Click `Launch instance`

2. **Connect to the EC2 Instance**:


```bash
-- Amazon Linux: 
ssh -A -i technbd-key.pem ec2-user@100.57.164.xx

-- Ubuntu:
ssh -A -i technbd-key.pem ubuntu@100.57.164.xx
```


_Test Connectivity:_
```bash 
telnet pgsql18-db-1.xxxxxxxx.us-east-1.rds.amazonaws.com 5432

nc -zv pgsql18-db-1.xxxxxxxx.us-east-1.rds.amazonaws.com 5432
```

```sql

```



_Create Database:_
```sql

CREATE DATABASE appdb OWNER appuser;

--Or,
CREATE DATABASE appdb;
ALTER DATABASE appdb OWNER TO appuser;
```
