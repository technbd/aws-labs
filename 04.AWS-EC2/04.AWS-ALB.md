## EC2 Load Balancing:

When you have multiple EC2 instances **running the same application**, an AWS Elastic Load Balancer (ELB) can distribute incoming traffic across them.




### AWS Load Balancer Types:

_AWS provides three main Elastic Load Balancer types:_
| Type     | Layer   | Main use                      |
| -------- | ------- | ----------------------------- |
| **ALB**  | Layer 7 | HTTP/HTTPS applications       |
| **NLB**  | Layer 4 | TCP/UDP/TLS, high performance |
| **GWLB** | Layer 3 | Network/security appliances   |

## Create Application Load Balancer (ALB):

To set up an AWS **Application Load Balancer (ALB)**, you need to login your AWS Management Console , create a Target Group for your backend servers, and then create the ALB to route traffic to that group. 



_Build it in this order:_
```
01. VPC
 ↓
02. Subnets
 ↓
03. Internet Gateway
 ↓
04. Route Table
 ↓
05. Security Groups x 2 
 ↓
06. EC2 × 2
 ↓
07. Target Group
 ↓
08. Register EC2 targets
 ↓
09. Application Load Balancer
 ↓
10. Listeners and routing
 ↓
11. Test
```

### Step 2: Create Security Group for ALB

1. Open the [CloudWatch Console](https://us-east-1.console.aws.amazon.com/console/home?region=us-east-1) in the **us-east-1 (N. Virginia)** region.
    - Open the **EC2 Console**.
    - Select `Security Groups` from the left menu under `Network & Security` section, and click `Create security group`: 
        - Security group name: `alb-sg`
        - Description: ALB security group
        - VPC: `(default)`
        - Inbound rules:
            - Type:       HTTP / HTTPS
            - Protocol:   TCP
            - Port:       80 / 443
            - Source:     Anywhere IPv4 
        - Click `Create security group` 


### Step 3: Create Security Group for EC2:
Create another security group:

1. Open the [CloudWatch Console](https://us-east-1.console.aws.amazon.com/console/home?region=us-east-1) in the **us-east-1 (N. Virginia)** region.
    - Open the **EC2 Console**.
    - Select `Security Groups` from the left menu under `Network & Security` section, and click `Create security group`: 
        - Security group name: `web-server-sg`
        - Description: web-server security group
        - VPC: `(default)`
        - Inbound rules:
            - Type:       HTTP
            - Protocol:   TCP
            - Port:       80
            - Source:     `Custom`
                - Security Groups: select `alb-sg` 
        - Inbound rules:
            - Type:       SSH
            - Protocol:   TCP
            - Port:       22
            - Source:     Anywhere IPv4 
        - Click `Create security group` 





### Step 4: Launch EC2 Instance 

1. Launch your instance· 

2. Configure your instance:  
    - Number of instances: `2`
    - Name and tags: `web-server-01`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` - (`ami-0f8a61b66d1accaee`)
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `(default)`
        - Subnet: (Default subnet in any availability zone)
        - Availability Zone: `us-east-1a`
        - Auto-assign public IP: `Enable`
        - Firewall (security groups): select existing security group (`web-server-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
    - Advanced details: 
        - User data - optional: below the data 
    - Then, `Launch instance`


_User data:_
```bash
#!/bin/bash

sudo apt update -y
sudo apt install apache2 -y 

echo "<h1>Server Details</h1><p><strong>Hostname:</strong> $(hostname)</p><p><strong>IP Address:</strong> $(hostname -I | cut -d ' ' -f1)</p>" > /var/www/html/index.html

sudo systemctl restart apache2
```



### Step 5: Create Target Group

1. Open the **EC2 Console**.
    - In the left menu, scroll down to `Load Balancing` - click `Target Groups` - click `Create target group`:
    - Choose Target type: select `Instances` 
        - Target group name: `web-alb-targets`
        - Protocol: `HTTP` 
        - Port: `80`
        - IP address type: `IPv4`
        - VPC: select VPC `(default)`
        - Protocol version: `HTTP1`
        - Health checks:
            - Health check protocol: `HTTP`
            - Health check path: `/`
        - Target optimizer - optional:
        - Click `Next`
        - Available instances: (Select the EC2 instances you want to include)
            - ✅ web-server-01
            - ✅ web-server-02
            - Ports for the selected instances: `80` 
            - click `Include as pending below` 
            - click Next
        - click `Create target group`




### Step 6: Create Application Load Balancer 

Now, you will create the actual ALB that sits in front of your instances.

1. In the left menu of the **EC2 console**.
    - In the left menu, scroll down to `Load Balancing` - click `Load balancers` - click `Create load balancer`:
    - Load balancer types: under the `Application Load Balancer` - click `Create`
    - Basic Configuration: 
        - Load balancer name: `web-alb`
        - Scheme: `Internet-facing`
        - Load balancer IP address type: `IPv4`
    - Network mapping:
        - VPC: select VPC `(default)`
        - Availability Zones and subnets: select ALL (at least two AZs)
    - Security groups:
        - Security groups: select `alb-sg`
    - Listeners and routing:
        - Protocol: `HTTP`
        - Port: `80` 
    - Default action:
        - Routing action: ✅ `Forward to target groups`
            - Target group: select `web-alb-targets`
    - Scroll to the bottom and click `Create load balancer`

2. Copy and paste that `DNS name` into your web browser. 

_Open in your browser:_
```
http://web-alb-xxxxxxx.us-east-1.elb.amazonaws.com
```

## Application Load Balancer (ALB) with HTTPS: 

1. Open **AWS Certificate Manager (ACM)** console - click `Request a certificate`:
    - Certificate type: `Request a public certificate` (Request a public SSL/TLS certificate from Amazon. By default, public certificates are trusted by browsers and operating systems.)
    - Click `Next`
    - Domain names:
        - Fully qualified domain name: `technbd.net`
    - Allow export: ✅ `Disable export` 
    - Validation method: ✅ `DNS validation`
    - Key algorithm: ✅ `RSA 2048`
    - Click `Request`
        - **Domains** section - click `Create records in Route 53`:
            - Select ✅` technbd.net`
            - Click `Create records` (<-- thats create CNAME record)


2. In the left menu of the **EC2 console**.
    - In the left menu, scroll down to `Load Balancing` - click `Load balancers` - select `web-alb`:
    - Click `Listeners and rules` - click `Add listener`:
    - Listener:
        - Protocol: `HTTPS`
        - Port: `443` 
    - Default action:
        - Pre-routing action: ✅ `No pre-routing action`
        - Routing action: ✅ `Forward to target groups`
            - Target group: select `web-alb-targets`
    - Secure listener settings:
    - Security policy:
        - Security category: `All secuiry policies`
        - Policy name: `ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09 (Recommended)`
    - Default SSL/TLS server certificate:
        - Certificate source: ✅ `From ACM` 
        - Certificate (from ACM): **select your certificate**
            - Or, click **Request new ACM certificate**: to redirect **AWS Certificate Manager** console
    - Client certificate handling:
    - Listener tags - optional: 
    - Click `Add listener`
    - Select your `web-alb` and copy **DNS name**


3. Open **Route 53** console - click `Hosted zones` - click your domain: `technbd.net`
    - Click `Create record` - click ✅ Alias (Enable)
        - Route traffic to: 
            - Choose endpoint: `Alias to Application and Classic Load Balancer`
            - Choose Region: `US East (N. Virginia)`
            - Choose load balancer: `web-alb`
            - Routing policy: `Simple routing` 
        - Click `Create records`


4. Open in your browser:

```
technbd.net
```
