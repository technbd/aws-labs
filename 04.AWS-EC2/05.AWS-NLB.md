## AWS NLB:

An AWS **Network Load Balancer (NLB)** operates primarily at **Layer 4** and is designed for high-performance TCP, TLS, and UDP traffic.




### NLB vs ALB:

This distinction is important:

| Feature               | NLB                          | ALB                     |
| --------------------- | ---------------------------- | ----------------------- |
| OSI layer             | Layer 4                      | Layer 7                 |
| TCP                   | ✅                            | ❌                       |
| UDP                   | ✅                            | ❌                       |
| TLS                   | ✅                            | ✅                       |
| HTTP                  | Pass-through/L4               | Native HTTP             |
| HTTPS                 | TLS pass-through/termination  | Native HTTPS            |
| Path routing          | ❌                            | ✅                       |
| Host routing          | ❌                            | ✅                       |
| Very high performance | ✅                            | ✅                       |
| Web applications      | Good                         | **Usually preferred**   |
| Static IP             | **Yes**                      | No fixed IP per AZ      |
| Target type           | Instance/IP/etc.             | Instance/IP/Lambda/etc. |

### Step 1: Create VPC



### Step 2: Create Security Group for NLB

1. Open the [CloudWatch Console](https://us-east-1.console.aws.amazon.com/console/home?region=us-east-1) in the **us-east-1 (N. Virginia)** region.
    - Open the **EC2 Console**.
    - Select `Security Groups` from the left menu under `Network & Security` section, and click `Create security group`: 
        - Security group name: `nlb-sg`
        - Description: NLB security group
        - VPC: `(default)`
        - Inbound rules:
            - Type:       HTTP / HTTPS  (<- NLB/client traffic as appropriate)
            - Protocol:   TCP
            - Port:       80 / 443
            - Source:     Anywhere IPv4 
        - Click `Create security group` 


### Step 3: Create Security Group for EC2:
Create another security group:

1. Open the [CloudWatch Console](https://us-east-1.console.aws.amazon.com/console/home?region=us-east-1) in the **us-east-1 (N. Virginia)** region.
    - Open the **EC2 Console**.
    - Select `Security Groups` from the left menu under `Network & Security` section, and click `Create security group`: 
        - Security group name: `web-server-sg`
        - Description: web-server security group
        - VPC: `(default)`
        - Inbound rules:
            - Type:       HTTP
            - Protocol:   TCP
            - Port:       80
            - Source:     `Custom`
                - Security Groups: select `nlb-sg` 
        - Inbound rules:
            - Type:       SSH
            - Protocol:   TCP
            - Port:       22
            - Source:     Anywhere IPv4 
        - Click `Create security group` 





### Step 4: Launch EC2 Instance 

1. Launch your instance· 

2. Configure your instance:  
    - Number of instances: `2`
    - Name and tags: `web-server-01`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` - (`ami-0f8a61b66d1accaee`)
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `(default)`
        - Subnet: (Default subnet in any availability zone)
        - Availability Zone: `us-east-1a`
        - Auto-assign public IP: `Enable`
        - Firewall (security groups): select existing security group (`web-server-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
    - Advanced details: 
        - User data - optional: below the data 
    - Then, `Launch instance`


_User data:_
```bash
#!/bin/bash

sudo apt update -y
sudo apt install apache2 -y 

echo "<h1>Server Details</h1><p><strong>Hostname:</strong> $(hostname) <strong> IP Address:</strong> $(hostname -I | cut -d ' ' -f1)</p>" > /var/www/html/index.html

sudo systemctl restart apache2
```



### Step 5: Create Target Group

1. Open the **EC2 Console**.
    - In the left menu, scroll down to `Load Balancing` - click `Target Groups` - click `Create target group`:
    - Choose Target type: select `Instances` 
        - Target group name: `web-nlb-tg`
        - Protocol: `TCP` 
        - Port: `80`
        - IP address type: `IPv4`
        - VPC: select VPC `(default)`
        - Health checks:
            - Health check protocol: `HTTP`
            - Health check path: `/`
        - Click `Next`
        - Register targets - recommended
        - Available instances: (Select the EC2 instances you want to include)
            - ✅ web-server-01
            - ✅ web-server-02
            - Ports for the selected instances: `80` 
            - click `Include as pending below` 
            - click Next
        - click `Create target group`




### Step 6: Create Network Load Balancer 

Now, you will create the actual NLB that sits in front of your instances.

1. In the left menu of the **EC2 console**.
    - In the left menu, scroll down to `Load Balancing` - click `Load balancers` - click `Create load balancer`:
    - Load balancer types: under the `Network  Load Balancer` - click `Create`
    - Basic Configuration: 
        - Load balancer name: `web-nlb`
        - Scheme: `Internet-facing`
        - Load balancer IP address type: `IPv4`
    - Network mapping:
        - VPC: select VPC `(default)`
        - Availability Zones and subnets: select ALL (at least two AZs)
    - Security groups:
        - Security groups: select `nlb-sg`
    - Listeners and routing:
        - Protocol: `TCP`
        - Port: `80` 
    - Forward to target group:
        - Target group: `web-nlb-tg`
    - Scroll to the bottom and click `Create load balancer`

2. Copy and paste that `DNS name` into your web browser. 


_Open in your browser:_
```
http://web-nlb-xxxxxxx.us-east-1.elb.amazonaws.com
```
