## AWS Bastion Host:

An **AWS bastion host** (also called a **jump host**) is an EC2 instance that acts as a secure entry point to access resources in a private subnet, such as EC2 instances, RDS databases, or Kubernetes worker nodes.


### Basic Architecture:

_Access Flow:_
- Users first connect to the Bastion Host using SSH.
- From the Bastion Host, they connect to the required private instance.
- Private instances remain secure because they do not require public IP addresses.

_Example:_
```
# Connect to bastion
ssh -i key.pem ec2-user@54.x.x.x

# From bastion to private server
ssh -i key.pem ec2-user@10.0.11.15
```


```
                Internet
                    │
             Public IP / Elastic IP
                    │
           +------------------+
           |  Bastion Host    |
           |  Public Subnet   |
           +------------------+
                    │
     Security Group allows SSH (22)
                    │
        Private VPC Network
          ┌──────────┴──────────┐
          │                     │
   Private EC2            Private RDS
   (No Public IP)         (No Public IP)
```


### How it works:
- An administrator connects to the bastion host using `SSH` (Linux) or `RDP` (Windows).
- From the bastion host, the administrator connects to private instances.
- Private instances never require public IP addresses or direct internet access.



### Requirements:
- A VPC with both Public and Private subnets is required to create a secure network environment.
- An Internet Gateway is needed to allow the Bastion Host to communicate with the internet.
- The architecture can span across two Availability Zones for better availability.
- Elastic IP addresses are required for Bastion Host instances.
- Amazon CloudWatch is used to store and monitor Bastion Hosts logs.
- Security Groups are configured to securely allow access between the Bastion Host and private instances. 




### Best practices:
- Place the bastion host in a **public subnet**.
- Place application servers in **private subnets**.
- Restrict inbound SSH/RDP access to specific corporate IP addresses.
- Use IAM roles instead of storing AWS credentials on the bastion.
- Enable logging with CloudWatch or AWS Systems Manager Session Manager.




#### Security Group Rules:

- Bastion SG: Inbound: Allow SSH (Port 22) ONLY from your **specific IP address** (e.g., 203.xx.xx.x/32). **Never allow** `0.0.0.0/0`.
- Private Instance SG:  Allow SSH (Port 22) ONLY **from the Bastion Security Group ID**. This ensures that only the Bastion can talk to your private servers.


| Rule     | Source                            | Description      |
| -------- | --------------------------------- | ---------------- | 
| SSH (22) | Allow your office/home IP only    | Bastion Host SG  |
| SSH (22) | Allow bastion Host Security Group | Private EC2 SG   |

## Bastion Host Setup: 



### Create Security Groups:

#### 1. Public Bastion Host Security Group:
1. Open the **VPC Console**.
    - Select `Security Groups` from the left menu under `Security` section, and click `Create security group`: 
        - Security group name: `bastion-sg`
        - Description: Security group for Bastion Host
        - VPC: select VPC `technbd-vpc`
        - **Inbound rules**:
            - Type:       `SSH` 
            - Protocol:   TCP
            - Port:       `22` 
            - Source:     **YOUR_PUBLIC_IP/32**
        - Click `Create security group` 


#### 2. Private Resources (EC2, DB) Security Group:

Allow SSH (Port 22) or the specific resource port (e.g., `3306` for MySQL, `5432` for PostgreSQL).

1. Open the **VPC Console**.
    - Select `Security Groups` from the left menu under `Security` section, and click `Create security group`: 
        - Security group name: `private-ec2-sg`
        - Description: private-ec2-resources access from baston host 
        - VPC: select VPC `technbd-vpc`
        - **Inbound rules**:
            - Type:       `SSH` 
            - Protocol:   TCP
            - Port:       22 
            - Source:     `Custom`
                - **Security Groups**: select `bastion-sg`
        - **Inbound rules (Optional)**:
            - Type:       `All ICMP - IPv4` 
            - Protocol:   `ICMP` 
            - Port:       `All`  
            - Source:     `Custom`
                - **Security Groups**: select `bastion-sg`
        - Click `Create security group` 




### Launch Bastion EC2: 

1. Launch your instance: 

2. Configure your instance:  
    - Number of instances: `1`
    - Name and tags: `bastion-host`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` 
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `technbd-vpc`
        - Subnet: select subnet `public-subnet-1` 
        - Auto-assign public IP: `Enable`
        - Firewall (security groups): select existing security group (`bastion-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
    - Advanced details: 
        - User data - optional: 
    - Then, `Launch instance`






### Launch Private EC2:


1. Launch your instance: 

2. Configure your instance:  
    - Number of instances: `1`
    - Name and tags: `web-server-01`
    - Amazon Machine Image (AMI): `Ubuntu Server 24.04 LTS` 
    - Instance type: `t3.micro` 
    - Key pair name (required): `technbd-key`
    - Network settings:
        - Network: select VPC `technbd-vpc`
        - Subnet: select subnet `private-subnet-1` or `private-subnet-2`
        - Auto-assign public IP: `Disable`
        - Firewall (security groups): select existing security group (`private-ec2-sg`)
    - Configure storage: `1x 8 GiB - gp3` (Root volume,3000 IOPS, Not encrypted)
    - Advanced details: 
        - User data - optional: 
    - Then, `Launch instance`



### Verify:

_Connect to Bastion:_
```
ssh -i "your-key.pem" ec2-user@<BASTION_PUBLIC_IP>
```


_On the bastion:_
```
chmod 400 mykey.pem
```


_Connect from Bastion to Private EC2:_
```
ssh -i mykey.pem ec2-user@10.0.11.50
```

## Better Method — SSH Agent Forwarding:

You need your private key (`mykey.pem`) to log into the private instance. But you should **NEVER copy your private key to the Bastion Host**. If the Bastion is compromised, your key is stolen.


### For MobaXterm:

Enable the option for `SSH agent` / `Pageant` if available in your version.

1. Open `MobaXterm` - `Settings` - `Configuration` - `SSH`:
    - SSH agents: 
        - ✅ `Use internal SSH agent "MobAgent"` 
        - Load fllowing keys at MobAgent startup - click plus sign `+`
            - `D:\aws\secret\mykey.pem`
        - ✅ `Use external Pageant` 
    - Click `OK`




_From your local machine:_
```
ssh -A -i mykey.pem ec2-user@98.81.72.57
```


_On the bastion host, run:_
```
ssh-add -l
```


_You should see your key:_
```
2048 SHA256:xxxxxxxxxxxxxxxxxxxxxxxx/HM Imported-Openssh-Key (RSA)
```




_Then from the bastion:_
```
ssh ec2-user@10.0.12.143
```

## Modern AWS Alternative:

AWS now recommends using **AWS Systems Manager Session Manager** instead of a bastion host whenever possible. Session Manager allows you to:

- Access EC2 instances without opening port 22.
- Eliminate public IPs on management instances.
- Log all sessions to CloudWatch Logs or S3.
- Integrate with IAM for fine-grained access control.
